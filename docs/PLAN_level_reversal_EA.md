# План: MT5-советник "Отскок от уровня с подтверждением" (Level Reversal EA)

Статус: **план, реализация не начата**. Документ фиксирует архитектуру, логику и порядок работ. По вопросам, на которые пользователь не дал явного ответа, приняты решения по умолчанию (помечены "⚙️ решение по умолчанию") — их можно пересмотреть перед реализацией.

---

## 1. Идея стратегии

1. На старшем таймфрейме (H4/D1) находим **сильные горизонтальные уровни** поддержки/сопротивления — цена отскакивала от них 2–3+ раза.
2. На старшем ТФ определяем **тренд / флэт**.
3. Когда цена на младшем ТФ подходит к сильному уровню:
   - если тренд восходящий — ищем только точки входа в **лонг** от поддержки;
   - если тренд нисходящий — ищем только **шорт** от сопротивления;
   - если флэт — разрешены сделки в обе стороны (лонг от поддержки, шорт от сопротивления).
4. Вход подтверждается **разворотным паттерном** на младшем ТФ у уровня: пин-бар, поглощение, доджи, молот/падающая звезда, двойное дно/двойная вершина.
5. Позиция открывается маркет-ордером на закрытии подтверждающей свечи, лот фиксированный (макс. 0.1), SL по ATR × множитель, TP = SL × коэффициент R:R (параметр, напр. 1:2 или 1:3).
6. Уровни визуально отрисовываются на графике (линии/зоны + подпись силы уровня).

---

## 2. Таймфреймы

- **Старший ТФ (уровни + тренд):** H4 и D1 — уровни ищутся на обоих, "сильный" уровень — это цена, где отскоки зафиксированы на масштабе H4/D1.
- **Младший ТФ (вход/паттерн):** M5 / M15 — задаётся входным параметром `ENUM_TIMEFRAMES InpEntryTF`. ⚙️ Пользователь подтвердил: **конкретный младший ТФ не фиксируем**, он подбирается экспериментально в ходе оптимизации в Python (перебор M5/M15 как ещё одного параметра/варианта прогона). EA поддерживает оба через один input-параметр.

---

## 3. Определение уровней (S/R)

⚙️ Решение по умолчанию (нет явного ответа пользователя): **уровни строятся по swing high/low на H4/D1**, а не по формулам Pivot/Camarilla/DeMark (в отличие от текущего `FV_Bounce.mq5`). Причина: пользователь явно описал критерий "цена отскакивала 2–3+ раза", это price-action подход, а не расчётные пивоты.

Алгоритм:
1. На H4 и на D1 независимо ищем локальные экстремумы (фракталы: high/low, которые выше/ниже N соседних баров слева и справа, N — параметр, например 2–3).
2. Экстремумы группируются в **кластеры уровней**: если два экстремума находятся в пределах буфера `LevelBufferATR × ATR(старший ТФ)` друг от друга — считаем их одним уровнем (цена уровня = среднее/медиана кластера).
3. Для каждого кластера считаем **количество касаний (touches)** — число раз, когда цена подходила в зону уровня ± буфер и разворачивалась.
4. Уровень считается **сильным**, если `touches >= MinTouches` (параметр, по умолчанию 3, диапазон для оптимизации 2–4).
5. Уровни, пробитые ценой на закрытии свечи с запасом (> `BreakBufferATR × ATR`), помечаются как "сломанные" и перестают использоваться как активные (либо меняют роль S↔R — это тоже вынести в параметр `InpFlipBrokenLevels`).
6. Список активных сильных уровней пересчитывается на каждом новом баре старшего ТФ (H4 и D1 отдельно, объединяются в общий список с меткой источника).

Параметры уровней (входы EA):
- `InpFractalDepth` — глубина фрактала для swing high/low (по умолчанию 2).
- `InpLevelBufferATR` — буфер кластеризации/касания, xATR старшего ТФ.
- `InpMinTouches` — минимум касаний для "сильного" уровня (по умолчанию 3, оптимизируется 2–4).
- `InpBreakBufferATR` — буфер подтверждения пробоя уровня.
- `InpMaxLevelsPerSide` — максимум хранимых активных уровней S и R (например, по 5 каждой стороны, ближайшие к цене).
- `InpLevelLookbackBars` — глубина истории (в барах старшего ТФ) для поиска уровней, например 250–500 баров H4/D1.

## 4. Определение тренда / флэта (старший ТФ)

⚙️ Решение по умолчанию: комбинация индикаторов, наиболее просто и надёжно реализуемая в MQL5:

- **EMA(50) vs EMA(200)** на H4 (и/или D1) — наклон и взаимное расположение:
  - EMA50 > EMA200 и обе растут → восходящий тренд → разрешён только лонг.
  - EMA50 < EMA200 и обе падают → нисходящий тренд → разрешён только шорт.
- **ADX(14)** как фильтр силы тренда: если `ADX < InpAdxFlatThreshold` (по умолчанию 20) → считаем рынок **флэтом**, разрешены обе стороны независимо от EMA.
- Если ADX выше порога, но EMA50/EMA200 не дают однозначного направления — трактуем как флэт (консервативно).

Параметры:
- `InpTrendTF` — таймфрейм для тренд-фильтра (по умолчанию H4, опционально проверять согласованность с D1).
- `InpEmaFast`, `InpEmaSlow` — периоды EMA (50/200).
- `InpAdxPeriod`, `InpAdxFlatThreshold`.

## 5. Подтверждающие разворотные паттерны (младший ТФ)

Все паттерны детектируются на **последней закрытой свече** младшего ТФ, при условии что её экстремум находится в зоне уровня (± `InpLevelBufferATR × ATR(младший ТФ)` либо отдельный буфер для входа `InpEntryZoneATR`).

Реализуемые паттерны (каждый — отдельная функция bool в MQL5):
1. **Пин-бар** — тело мало относительно диапазона (`body <= K1 × range`), длинная тень в сторону уровня (`shadow_to_level >= K2 × range`), короткая противоположная тень.
2. **Поглощение (engulfing)** — тело текущей свечи полностью перекрывает тело предыдущей, направление разворотное относительно предыдущего тренда/касания.
3. **Доджи** — тело близко к нулю (`body <= K3 × range`), не является единственным условием входа — используется как дополнение к другим сигналам либо требует последующего подтверждения следующей свечой (параметр `InpDojiNeedsConfirmation`).
4. **Молот / падающая звезда** — частный случай пин-бара с уточнённым положением тела (в верхней/нижней трети диапазона).
5. **Двойное дно / двойная вершина на уровне** — два локальных экстремума младшего ТФ примерно на одной цене (в пределах буфера) с разворотом между ними (需 middle swing противоположного знака), оба экстремума — в зоне уровня.

Каждый паттерн включается/выключается отдельным bool-параметром (`InpUsePinBar`, `InpUseEngulfing`, `InpUseDoji`, `InpUseHammerStar`, `InpUseDoubleTopBottom`), сигнал на вход = **любой из включённых паттернов сработал** (OR-логика), либо параметром переключается на "требовать минимум N паттернов" для более строгого фильтра.

Коэффициенты паттернов (K1, K2, K3, доля тела для молота/звезды) выносятся в параметры для последующей оптимизации в Python.

## 6. Правила входа

1. Тренд-фильтр (п.4) определяет разрешённые стороны (лонг/шорт/обе).
2. Цена младшего ТФ должна находиться в **зоне сильного уровня** (S — для лонга, R — для шорта), уровень не должен быть "сломанным".
3. На закрытии свечи младшего ТФ в этой зоне сработал хотя бы один включённый разворотный паттерн, соответствующий нужному направлению.
4. Вход — **маркет-ордер сразу на открытии следующей свечи после закрытия подтверждающей** (⚙️ решение по умолчанию — просто и надёжно исполняется, минимизирует риск невхода в отличие от отложенного ордера).
5. Не более одной активной позиции одновременно (⚙️ решение по умолчанию — проще управлять риском при депозите $700 и лоте 0.1). Пока есть открытая позиция — новые сигналы игнорируются.
6. Проверка `InpMagic`, спред/сессии — базовые защитные проверки (не открывать при аномальном спреде).

## 7. Управление риском

- Символ: **EURUSD**, стартовый депозит: **$700** (используется в Python-бэктесте и как справочное значение для проверки маржи в EA).
- Объём сделки: **фиксированный, не более 0.1 лота** (⚙️ решение по умолчанию — простой фиксированный лот 0.1, без риск-процента; параметр `InpLot` с проверкой `NormalizeLot` и капом на 0.1, как в текущем `FV_Bounce.mq5`).
- **SL** = `InpSlAtrMult × ATR(InpAtrTF, InpAtrPeriod)` от цены входа. ТФ для ATR по умолчанию — **тот же младший ТФ входа** (⚙️ решение по умолчанию — SL должен отражать волатильность момента входа).
- **TP** = `SL_distance × InpRR`, где `InpRR` — параметр соотношения TP/SL (например 2.0 = 1:2, 3.0 = 1:3), задаётся числом с плавающей точкой, чтобы поддержать произвольные соотношения при оптимизации.
- Доп. защитные механики (break-even, трейлинг, фильтр часов, лимит сделок/день) — по умолчанию **выключены** (не запрошены явно), но входные параметры-заглушки закладываются в архитектуру заранее, чтобы включить их позже без переписывания структуры:
  - `InpUseBreakEven`, `InpBreakEvenAtrMult` (0 = выкл).
  - `InpUseTrailing`, `InpTrailAtrMult` (0 = выкл, аналогично текущему EA).
  - `InpTradeStartHour` / `InpTradeEndHour` (0–23, по умолчанию весь день).
  - `InpMaxTradesPerDay` (0 = без лимита).

## 8. Визуализация уровней на графике

Отрисовка через объекты MQL5 (`OBJ_HLINE` или `OBJ_TREND`/`OBJ_RECTANGLE` для зоны буфера), обновляется при пересчёте уровней:

- Линия/зона поддержки — зелёный цвет, сопротивления — красный.
- Толщина/стиль линии зависит от количества касаний (например, 3 касания — тонкая пунктирная, 4+ — толще сплошная).
- Подпись (`OBJ_TEXT` рядом с линией): `S/R | touches=N | TF=H4|D1 | status=active/broken`.
- Отдельный цвет/стиль для "сломанных" уровней (например, серый, оставлять на графике для истории или удалять по параметру `InpKeepBrokenLevels`).
- Все объекты именуются с префиксом (например `FVLR_S_...`, `FVLR_R_...`) и очищаются/пересоздаются в `OnDeinit` и при пересчёте, чтобы не копить старые объекты на графике.

## 9. Оптимизация параметров через Backtesting.py (Python)

### 9.1 Данные
В `content/` сейчас есть только `EURUSD_H1_2020-01-01_2025-12-31.csv`. Для стратегии нужны бары **M5/M15 (вход/паттерны)** и **H4/D1 (уровни/тренд)**.

**Экспорт данных берёт на себя пользователь** — он самостоятельно выгрузит из MT5 и положит в `content/` историю EURUSD по M5, M15, H4, D1 за нужный период (формат/имена файлов — как у существующего `EURUSD_H1_2020-01-01_2025-12-31.csv`, либо будет уточнено при загрузке). Задача пайплайна — только прочитать эти CSV, привести к единому формату (индекс времени, колонки `Open/High/Low/Close/Volume`) и свериться по датам между таймфреймами.
- Если старшие ТФ (H4/D1) из MT5 будут отличаться по времени открытия сессии/барам от ресемпла младшего ТФ — использовать напрямую загруженные H4/D1 файлы как источник истины для уровней и тренда (не ресемплить из M5/M15), чтобы точно соответствовать тому, что видит EA в MT5 через `iHigh`/`iLow` на H4/D1.
- M10 в план не включён, т.к. данные по нему не предоставляются; при необходимости добавляется позже аналогично M5/M15.

### 9.2 Архитектура пайплайна оптимизации
- Реализация уровней/тренда/паттернов **дублируется в Python** (аналогично тому, как в `content/*.ipynb` уже есть логика бэктеста для текущего EA) в виде класса `Strategy` для `backtesting.py`, максимально зеркально повторяя логику MQL5, чтобы результаты совпадали при переносе в MT5 (как это сделано для `bounce_atr_opt.py` / `FV_Bounce.mq5`).
- Тестируется отдельно для каждого варианта младшего ТФ (M5 / M15) — выбирается тот, что даёт наилучшие устойчивые метрики (не только по чистой прибыли, но и по просадке/стабильности).
- Оптимизируемые параметры (через `Backtest.optimize`, метод `grid` или `sambo`/`skopt` при большом пространстве):
  - `MinTouches` (2–4)
  - `LevelBufferATR`, `BreakBufferATR`, `EntryZoneATR`
  - `FractalDepth`, `LevelLookbackBars`
  - `EmaFast`, `EmaSlow`, `AdxPeriod`, `AdxFlatThreshold`
  - Коэффициенты паттернов (K1/K2/K3 и т.п.), включение/выключение каждого паттерна
  - `SlAtrMult`, `RR` (1:1.5 / 1:2 / 1:3 и промежуточные)
  - ATR-период для SL
- Ограничения при оптимизации: лот фиксирован 0.1, депозит $700, комиссия/спред EURUSD берутся реалистичные (учитывать спред из данных или фиксированный в пунктах).
- Walk-forward / train-test split по времени (например, 2020–2023 — подбор, 2024–2025 — проверка "из выборки"), чтобы избежать переобучения — обязательный шаг перед переносом параметров в MT5.
- Метрики отбора: Return, Max Drawdown, Sharpe/Sortino, Win Rate, Profit Factor, количество сделок (не слишком мало для статистической значимости).

### 9.3 Результат пайплайна

## 12. Риски и предупреждения

- Это торговая стратегия для финансовых рынков — результаты бэктеста не гарантируют будущую прибыль, возможны убытки вплоть до полной потери депозита $700.
- Малый депозит + лот 0.1 на EURUSD означает высокую относительную волатильность просадки — требуется консервативный SL/риск на сделку.
- Свечные паттерны на M5/M15 дают много ложных сигналов — обязателен walk-forward тест, а не только оптимизация на всей истории (риск переобучения/оверфиттинга).
