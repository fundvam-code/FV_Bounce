# FV_Bounce: советник на отскок от уровней с RNN-фильтром (GRU/LSTM) и A/B-режимом с/без фильтра

> Generated by Deep Copilot · Plan mode

## 目标 / Goal
Построить торговую систему, которая торгует отскоки от свинг-уровней лимитными ордерами, а решение о входе опционально фильтрует RNN-сетью (GRU или LSTM), предсказывающей вероятность прибыльной сделки. Стратегию можно тестировать в двух режимах — с RNN-фильтром и без него — на этапе оптимизации (в ноутбуке через backtesting.py) и в терминале (MQL5-советник с переключателем). Параметры стратегии подбираются через backtesting.py, гиперпараметры сети — через Optuna. Сырые данные (CSV) пользователь предоставляет самостоятельно.

## 方案 / Approach
Двухэтапный конвейер с явным A/B-разделением. Этап 1: базовая стратегия отскока (свинг-уровни за N баров, лимитники, SL/TP по ATR, безубыток с буфером) реализуется в backtesting.py и оптимизируется в режиме «base» (без RNN) через bt.optimize(). Этап 2: оптимизированные параметры используются для разметки — по каждой точке касания симулируется сделка, лейбл = 1 если TP сработал раньше SL. Обучаются две бинарные RNN-сети (лонг/шорт), архитектуру (GRU/LSTM) и гиперпараметры подбирает Optuna с walk-forward CV на 2020–2024; 2025 — финальный тест. Затем A/B-сравнение на 2025: «base без фильтра» против «base + RNN-фильтр» с выбором порога; после — повторная оптимизация в режиме «rnn». MQL5-советник получает входной параметр UseRNNFilter (false = базовая стратегия, true = RNN-фильтр через ONNX и порог). Оба режима прогоняются в Strategy Tester и сверяются с ноутбуком. Исходный CSV кладётся пользователем в data/raw/.

## 步骤 / Steps
1. **Ноутбук 1–3: загрузка и подготовка** — Импорты/константы/seed, чтение CSV из data/raw (предоставлен пользователем), типы, проверки времени и отсутствия пропусков.
2. **Блок 4: базовая стратегия (без RNN)** — Свинг-уровни, лимитники, SL/TP по ATR, безубыток с буфером, выход по времени — без фильтра.
3. **Блок 5: оптимизация режим base** — bt.optimize() по: период уровня, sl_atr, tp_atr, триггер/буфер безубытка, max_hold, время жизни уровня. Без RNN.
4. **Блок 6: разметка лейблов** — Симуляция сделок в точках касания (зона 0.05 ATR) по оптимизированным параметрам: 1 = TP раньше SL, 0 = SL/выход по времени.
5. **Блок 7: признаки** — Окно нормализованных OHLCV + свойства уровня (тип, сила, число касаний, расстояние).
6. **Блок 8: разбиение** — 2020–2024 = train, 2025 = test; Optuna использует walk-forward CV на train.
7. **Блоки 9–10: две RNN + Optuna + обучение** — Лонг/шорт отдельно; Optuna: GRU/LSTM, hidden size, слои, lr, dropout, длина окна; class weights, early stopping.
8. **Блок 11: A/B-сравнение на 2025** — base (без фильтра) vs base+RNN: доходность, Sharpe, win rate, drawdown, число сделок; выбор порога по F1/прибыли.
9. **Блок 12: оптимизация режим rnn + экспорт** — Повторная оптимизация с включённым фильтром (порог, перепроверка параметров). Экспорт весов, ONNX, параметров, порога, отчёта A/B.
10. **MQL5-советник FV_Bounce_EA.mq5** — input UseRNNFilter (false/true); false = базовая стратегия, true = загрузка ONNX + порог фильтра. Признаки в FeatureCalc.mqh.
11. **Strategy Tester: сверка обоих режимов** — Прогон base и rnn в тестере на тех же данных, сверка метрик с ноутбуком.

## 风险与缓解 / Risks
- Нет валидационной выборки — риск переобучения выбора модели на 2025; митигируется walk-forward CV на 2020–2024 и единственной финальной оценкой.
- Дисбаланс классов — class weights.
- A/B-сравнение корректно только при полном совпадении логики ноутбука (backtesting.py) и советника (MQL5): уровни, зона касания, SL/TP, безубыток — нужна сверка на контрольных сделках.
- Расхождение симуляции и реального MT5 (спред, проскальзывание, исполнение лимитников) — держим стратегию простой и фиксируем допущения.
- 5 лет H1 ≈ 31k баров для двух классов и LSTM может быть мало — компактная сеть + регуляризация.
- Две сети удваивают время обучения и инференса — ограничить число Optuna trial.
- Экспорт LSTM/GRU в ONNX для MT5 — проверить поддержку операций ONNX-рантаймом терминала.

## 备注 / Notes
Сквозной режим A/B: в ноутбуке оптимизация выполняется дважды (base без RNN, затем rnn с фильтром) и строится сравнительный отчёт; в советнике это входной параметр UseRNNFilter. Лейбл разрешается в течение max_hold баров (TP раньше SL = 1); прогноз — в момент касания уровня; сеть выдаёт вероятность прибыльной сделки, вход при вероятности выше порога.
