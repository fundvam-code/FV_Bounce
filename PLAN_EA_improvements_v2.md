# План улучшений: level_reversal_ea.mq5 (v2)

Статус: **план, реализация не начата** (кроме п.0, который уже сделан). Документ фиксирует архитектуру доработок советника `level_reversal_ea.mq5` по двум запросам:
1. Линии уровней должны обновляться при каждом фактическом пересчёте.
2. Два режима входа в позицию — старый (отложенные ордера, авто-исполнение, логика в духе `FV_Bounce.mq5`) и новый (подтверждение паттерном на младшем ТФ, market-ордер), с переключением параметром, плюс поддержка M1 как таймфрейма входа/паттерна.

---

## 0. Уже сделано (быстрый фикс)

**Проблема:** `VisualizeLevels()` в `OnInit()` не вызывался вообще (линии появлялись только после первого нового H4-бара), а в `OnTick()` вызывался безусловно при смене H4-бара — даже если `RecalculateLevels()` внутри рано вышел (например, из-за часового троттлинга `TimeCurrent() - g_last_level_recalc < 3600`).

**Решение:** `RecalculateLevels()` теперь возвращает `bool` (true = уровни реально пересчитаны). `VisualizeLevels()` вызывается в `OnInit()` и в `OnTick()` **только** когда `RecalculateLevels()` вернул `true` — т.е. линия обновляется ровно тогда, когда произошёл расчёт уровня, включая самый первый запуск советника.

## 1. Идея: два режима входа

### Режим A — "Pending" (старый, в духе `FV_Bounce.mq5`)
- От найденного уровня (swing S/R, как сейчас считает `RecalculateLevels()`) выставляется **отложенный ордер** заранее:
  - `Buy Limit` = `support + InpPendingBufferATR × ATR(младший ТФ)` — вход в лонг на отскоке от поддержки.
  - `Sell Limit` = `resistance − InpPendingBufferATR × ATR(младший ТФ)` — вход в шорт на отскоке от сопротивления.
- **Без подтверждения паттерном** — исполнение чисто по достижению цены (как сейчас работает `FV_Bounce.mq5`).
- Ордера пересоздаются раз в `InpPendingIntervalMinutes` (аналог `InpOrderIntervalHours` из `FV_Bounce.mq5`, но в минутах — на младшем ТФ интервал логичнее короче): старые свои отложенные снимаются, ставятся новые по актуальным уровням/ATR.
- SL/TP/трейлинг — свои множители ATR для этого режима (`InpPendingSlAtrMult`, `InpPendingRR`, `InpPendingTrailAtrMult`), независимые от режима B, чтобы можно было оптимизировать раздельно.
- Не ставим повторно, если уже есть открытая позиция от этой стороны (аналог `HasPositionComment` из `FV_Bounce.mq5`) — переиспользуем эту функцию как есть.

### Режим B — "Pattern" (текущий, новый)
- Действующая логика без изменений: маркет-ордер на закрытии свечи младшего ТФ, где сработал pin bar / engulfing / doji в зоне уровня, с фильтром тренда (EMA+ADX).

### Переключение
```mql5
enum ENUM_ENTRY_MODE {
   ENTRY_MODE_PATTERN = 0,   // Новый: подтверждение паттерном, market-ордер
   ENTRY_MODE_PENDING = 1    // Старый: отложенные ордера, авто-исполнение
};
input ENUM_ENTRY_MODE InpEntryMode = ENTRY_MODE_PATTERN;  // Режим входа
```
Дефолт — `ENTRY_MODE_PATTERN`, чтобы не менять поведение по умолчанию для уже настроенных пользователей.

`OnTick()` разветвляется в начале:
```mql5
if(InpEntryMode == ENTRY_MODE_PENDING)
   ManagePendingEntries();   // новая функция, режим A
else
   ManagePatternEntries();   // текущее тело OnTick (логика паттернов), режим B
```
Обе ветки продолжают использовать общие `RecalculateLevels()`/`VisualizeLevels()`/`GetTrendDirection()` — уровни и тренд не дублируются.

## 2. Поддержка M1 (и произвольного выбора младшего ТФ)

Текущий enum:
```mql5
enum ENUM_TF_SELECT {
   TF_M5  = 5,
   TF_M15 = 15,
};
```
Добавить M1:
```mql5
enum ENUM_TF_SELECT {
   TF_M1  = 1,    // 1 минута
   TF_M5  = 5,    // 5 минут
   TF_M15 = 15,   // 15 минут
};
input ENUM_TF_SELECT InpEntryTF = TF_M5;   // дефолт остаётся M5, а не M1
```
`GetEntryTF()` дополнить веткой `TF_M1 → PERIOD_M1`.

**Важно (риск):** M1 даёт намного больше шума на паттернах (pin bar/doji на M1 малоинформативны) и на отложенных ордерах (частое переставление). Рекомендация — дефолт оставить M5, но разрешить M1 как экспериментальный вариант для оптимизации в Python (`level_reversal_opt.ipynb` тоже можно прогнать на M1 при наличии данных, если пользователь захочет — отдельная, необязательная задача).

## 3. Новые входные параметры (сводка)

```mql5
input group             "=== РЕЖИМ ВХОДА ==="
input ENUM_ENTRY_MODE  InpEntryMode        = ENTRY_MODE_PATTERN; // Режим входа: Pattern / Pending

input group             "=== PENDING: отложенные ордера (режим A) ==="
input double           InpPendingBufferATR   = 0.25;  // Буфер входа от уровня, xATR младшего ТФ
input int              InpPendingIntervalMin = 60;    // Интервал переустановки ордеров, минут
input double           InpPendingSlAtrMult   = 2.0;    // SL, xATR младшего ТФ
input double           InpPendingRR          = 2.0;    // TP = SL × RR
input double           InpPendingTrailAtrMult= 0.0;    // Трейлинг, xATR (0 = выкл)
```
Группа "ВХОД И ПАТТЕРНЫ" (Pattern-режим) остаётся как есть, плюс `TF_M1` в `ENUM_TF_SELECT`.

---

## 4. Что переиспользуется из `FV_Bounce.mq5`

| Из `FV_Bounce.mq5` | Как переиспользуется в режиме A |
|---|---|
| `CancelPending()` | Снятие своих отложенных перед переустановкой (по магику) |
| `HasPositionComment()` | Не дублировать вход, если позиция от этой стороны уже открыта |
| Периодическая переустановка ордеров (`g_last_manage` + интервал) | Аналогичный таймер `g_last_pending_manage` + `InpPendingIntervalMin` |
| `NormalizeLot()` / `NormalizePrice()` | Уже есть в `level_reversal_ea.mq5`, без изменений |
| Трейлинг по ATR с меткой в комментарии ордера | `TrailOnePosition`-аналог, различающий комментарии `"Pending_Sup"` / `"Pending_Res"` |

Уровни для режима A берутся не по Pivot/Camarilla/DeMark (как в `FV_Bounce.mq5`), а по уже существующим `GetNearestSupportLevel()`/`GetNearestResistanceLevel()` (swing high/low), чтобы оба режима работали на одной и той же карте уровней.

## 6. Риски

- Частая переустановка отложенных ордеров на коротких интервалах (M1 + короткий `InpPendingIntervalMin`) может упираться в ограничения брокера (`SYMBOL_TRADE_STOP_LEVEL/FREEZE_LEVEL`) — нужна проверка перед боевым использованием.
- Два режима с разными наборами параметров усложняют оптимизацию — держать оптимизацию раздельной (не мешать параметры режимов A и B в одном прогоне).
- M1-паттерны статистически менее надёжны — рекомендуется по умолчанию M5, M1 — только для экспериментов.
